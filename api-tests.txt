API Test Suite - Petstore Pet Endpoints

Total: 23 test executions (20 unique, findByStatus parametrized x3)

========================================
Tools / Frameworks
========================================

Tool                    Version   Purpose
----------------------  -------   ----------------------------------------
Python                  3.13      Language
Playwright for Python   1.60      APIRequestContext for HTTP calls
pytest                  9.0       Test runner, fixtures, assertions

Playwright's APIRequestContext is used for all API HTTP calls.
UI and API tests must be run in separate pytest sessions to avoid
asyncio conflicts caused by pytest-playwright's event loop.


========================================
How to Run
========================================

Install dependencies (first time only):
    pip install pytest playwright pytest-playwright
    playwright install chromium

IMPORTANT: UI and API tests must be run separately.

Run API tests only:
    python -m pytest api/tests/ -v

Run UI tests only:
    python -m pytest ui/tests/ -v

========================================
Design Decisions
========================================

CRUD coverage first
    TC-PET-01/02/03/10 form a full create > read > update > delete chain.

Consolidated update + verify
    TC-PET-03 does PUT then GET in one test — avoids dependency between tests
    while still verifying persistence.

All three valid statuses parametrized
    TC-PET-05/06/07 driven by valid_statuses array from api_test_data.json.

Edge cases document actual server behavior
    TC-PET-11 through TC-PET-24 test inputs not specified in the Swagger spec
    and document how the real server handles them (often more leniently than expected).

Multipart upload uses separate context
    upload_pet_client fixture has no Content-Type: application/json header
    so Playwright can set multipart/form-data boundary automatically.

All values from JSON
    Payloads, ids, names, expected statuses, and edge case inputs all loaded from
    test_data/api/api_test_data.json.

HTTP status codes from JSON
    HTTP_STATUS["ok"], HTTP_STATUS["not_found"] etc. — no hardcoded 200/404 in tests.

Factory method pattern
    PetApiClient.build_payload() centralizes payload construction.
