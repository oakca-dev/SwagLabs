========================================
How to Run
========================================

Install dependencies (first time only):
    pip install pytest playwright pytest-playwright
    playwright install chromium

Run all UI tests:
    python -m pytest ui/tests/ -v

Run a specific test file:
    python -m pytest ui/tests/test_auth.py -v
    python -m pytest ui/tests/test_cart.py -v
    python -m pytest ui/tests/test_checkout.py -v
    python -m pytest ui/tests/test_inventory.py -v

Run a single test by name:
    python -m pytest ui/tests/test_auth.py::TestAuthentication::test_user_can_login -v

Run in headed mode (see the browser):
    python -m pytest ui/tests/ -v --headed

NOTE: Run UI and API tests separately. See api-tests.txt for API instructions.


========================================
Why These Flows Were Selected
========================================

The four flows cover the complete critical path a real user follows:
authenticate → browse products → manage cart → complete purchase.
These are the highest-risk areas for regressions. Every other feature
(sorting, validation, session management) directly supports this path.

FLOW 1 - Authentication (test_auth.py)
----------------------------------------

Why: Login is the entry point to the entire application. Any regression
here blocks all other user flows. Validation and access control are
also high-risk areas.

---------  ----------------------------------------------------------------

           problem, error, visual users)
           - Verifies landing on inventory page with products visible

TC-AUTH-02 Locked out user sees correct error message
           - Verifies full error text: "Epic sadface: Sorry, this user
             has been locked out."

TC-AUTH-03 Wrong password shows credentials error
           - Verifies full error text: "Epic sadface: Username and
             password do not match any user in this service"

TC-AUTH-04 Blank username shows validation error
           - Verifies full error text: "Epic sadface: Username is required"

TC-AUTH-05 Blank password shows validation error
           - Verifies full error text: "Epic sadface: Password is required"

TC-AUTH-06 Logout from inventory page returns to login page
           - Verifies login button visible after logout

TC-AUTH-07 Unauthenticated user navigating directly to /inventory.html
           is redirected to login page

========================================
Design Decisions
========================================

Parametrized login
    TC-AUTH-01 runs once per valid user (standard, problem, error, visual)
    to catch user-specific rendering differences without duplicating test code.
    performance_glitch_user is excluded — deliberate slowness causes timeouts.

Full error message verification
    Auth error tests use to_have_text() (exact match) rather than
    to_contain_text() to catch truncation or wording regressions.

Price accuracy assertion
    TC-CHK-06 uses pytest.approx with abs=0.01 tolerance to handle
    floating point precision without false failures.

Autouse fixtures for login
    TestCart and TestInventory use autouse=True on the _login fixture
    to ensure every test in those classes starts from a clean logged-in state
    without repeating login code in each test.

Page Object Model
    All locators and actions are encapsulated in page classes under ui/pages/:
    LoginPage, InventoryPage, CartPage, CheckoutFillInfoPage,
    CheckoutSummaryPage, CheckoutCompletePage.
    Test files contain no raw selectors.

Test data externalised
    Credentials, product names, error messages, and checkout data are all
    loaded from test_data/ui/ui_test_data.json. No hardcoded values in tests.
