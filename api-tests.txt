API Test Suite - Petstore Pet Endpoints

========================================
Tools / Frameworks
========================================

Tool                    Version   Purpose
----------------------  -------   ----------------------------------------
Python                  3.13      Language
Playwright for Python   1.60      APIRequestContext for API calls, browser automation for UI
pytest                  9.0       Test runner, fixtures, assertions

Playwright's APIRequestContext is used for all API HTTP calls.
UI and API tests must be run in separate pytest sessions to avoid
asyncio conflicts caused by pytest-playwright's event loop.


========================================
How to Run
========================================

Install dependencies (first time only):
    pip install pytest playwright pytest-playwright
    playwright install chromium

IMPORTANT: UI and API tests must be run separately.
Playwright's sync API cannot run inside the asyncio event loop started
by pytest-playwright when UI and API tests run in the same session.

Run API tests only:
    python -m pytest api/tests/ -v

Run UI tests only:
    python -m pytest ui/tests/ -v

Test Architecture
=================

- API interactions encapsulated in PetApiClient
- pytest fixtures manage test data lifecycle
- Shared setup centralized in conftest.py
- Test data externalized to JSON


========================================
Design Decisions
========================================

CRUD coverage first
    TC-PET-01 through TC-PET-04 form a full create > read > update > verify
    chain, covering the core lifecycle of a pet resource.

All three valid statuses tested
    TC-PET-05/06/07 are parametrized with valid_statuses from api_test_data.json.
    Each verifies that findByStatus returns only pets matching the requested status.

Documented actual vs. spec behavior
    The Swagger spec states findByStatus should return 400 for invalid values
    and POST /pet requires photoUrls. The actual server behaves differently
    (returns 200 in both cases). Tests document the real behavior rather than
    the spec, with comments explaining the discrepancy.

Invalid id edge cases
    TC-PET-12/13/14 document how the server handles missing, string, and
    malformed id values — behaviors not specified in the Swagger spec.

Multipart upload context
    TC-PET-15 uses a dedicated upload_pet_client fixture with a separate
    APIRequestContext that omits Content-Type: application/json, since
    Playwright automatically sets the correct multipart/form-data boundary
    header when using the multipart= parameter.

Shared server awareness
    Since Petstore is a shared public environment, resource data can be modified 
    by other clients at any time. TC-PET-04 re-applies the update immediately before 
    retrieval to mitigate potential race conditions and concurrent writes.

Cleanup in every test
    Tests that create pets clean up after themselves (via fixture teardown or
    inline delete) to avoid polluting the shared server.

Test data driven
    All payloads, expected values, and edge case inputs are loaded from
    test_data/api/api_test_data.json — no hardcoded values in test files.
